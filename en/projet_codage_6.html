Sonumen - iOS music player for local libraries and personal servers

An advanced iOS prototype designed to bring a premium music experience to personal sources: local files, Jellyfin and Plex.

Role
Product design, iOS architecture, mobile UI and Swift development
Context
Personal project · Advanced prototype
Year
2026
Type
iOS mobile app

Project summary

Sonumen is an iOS prototype for a personal music player. The idea is to recover the feeling of a polished music app, but applied to a library the user actually controls: locally imported tracks, a self-hosted Jellyfin server or a Plex server.

The project is not trying to reproduce a streaming service. It explores a more specific question: how to offer a refined music interface while letting users decide where their files live.

Why this project

The need came from a simple frustration: personal music solutions often offer a lot of freedom, but with a mobile experience that feels less fluid or less finished than mainstream music apps. Sonumen starts from that tension between owning a library and keeping the experience enjoyable.

The goal is to build an iOS player that can handle multiple sources without making the interface feel technical or scattered. Users should be able to listen, find, organize and resume music without feeling the complexity behind the app.

Architecture & music sources

The app is built around a source-based architecture. Each source can load its own library and expose tracks through a shared model, which keeps the interface unified.

  • Local library: audio file import from iPhone or iPad
  • Jellyfin: self-hosted server connection, library selection and synchronization
  • Plex: personal server connection and music library retrieval
  • Shared model: tracks, albums, artists, playlists, favorites and history handled through the same logic

This makes the project easier to evolve: the interface does not need to be rewritten for each source, and playback behavior can remain coherent across local files and personal servers.

Settings dedicated to music sources: local library, Jellyfin server and Plex server.

Playback, library and persistence

The technical work goes beyond displaying tracks. Sonumen manages a real library layer with import, metadata, artwork, favorites, user playlists, playback history and playback state.

  • Audio playback through AVFoundation
  • Compatible audio file import and duplicate detection
  • Track metadata extraction and editing
  • Embedded and custom artwork handling
  • Favorites, playlists and history persisted locally
  • Error handling for missing files, unavailable remote sources and playback failures

I paid particular attention to the less visible cases that matter in a music player: keeping playback stable when a network source disappears, avoiding duplicate imports, and preserving a coherent library over time.

Music library with navigation across tracks, albums and imported content.

Interface & mobile experience

The interface combines UIKit for the main shell and custom transitions, with SwiftUI for several content screens. This keeps the mobile foundation robust while allowing faster iteration on views.

  • Modern tab bar with persistent mini player
  • Custom transition from mini player to full now playing screen
  • Full-screen playback view with artwork, controls, favorites, queue and playback options
  • Search, album/artist navigation, playlists and recently played tracks
  • Advanced native iOS integrations: system playback controls, external player, widgets and Live Activity
  • Settings dedicated to local, Jellyfin and Plex sources

The UI work focuses on the feeling of use: making the app feel native, fluid and coherent, without turning server features into an admin interface. The next iterations are mostly about UX polish for these entry points and making them feel consistent with the rest of the app.

Persistent mini player and transition to the full now playing screen.

Current state

Sonumen is currently an advanced, buildable prototype. The main building blocks are in place: local library, playback, persistence, favorites, playlists, history, settings, Jellyfin and Plex. It still needs product and technical validation before being treated as a finished app.

  • Native iOS app built with Swift, UIKit and SwiftUI
  • Around 90 Swift files in the project
  • Simulator build validated with Xcode
  • Unit tests covering library search and persistence behavior

Next steps

My final goal is to bring Sonumen to the App Store. Before that, the project needs a stabilization phase: testing with real libraries, validating Jellyfin/Plex connections, polishing the UI, making network playback reliable and clarifying the product positioning.

The next logical step would be a TestFlight phase to gather feedback from real users, followed by App Store preparation: product page, screenshots, privacy policy, clear wording and launch communication.

What this project helped me develop

  • An iOS architecture able to unify multiple music data sources
  • Stronger understanding of AVFoundation, local persistence and audio error cases
  • A product approach around a personal app designed with wider distribution in mind
  • A mobile interface workflow focused on fluidity, playback continuity and polish
