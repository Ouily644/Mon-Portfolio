Développement Suivea v3

Transformation de maquettes Suivea v3 en écrans web intégrés, avec une base de composants réutilisables pour fiabiliser les évolutions du produit.

Rôle
Intégration front-end en binôme
Contexte
Stage MMI2 · Docaposte · Suivea
Période
Mai 2021 - Juillet 2021
Type
Développement web

Résumé du projet

Dans le prolongement de la refonte graphique de Suivea, j'ai participé à l'intégration front-end d'une nouvelle version du produit pendant mon stage chez Docaposte. Le travail ne consistait pas seulement à "reproduire une maquette", mais à transformer une direction UI validée en écrans web cohérents, exploitables et maintenables.

L'enjeu était double : obtenir un rendu fidèle aux maquettes sur les écrans livrés, tout en posant une base de composants et de règles UI réutilisables pour les développements suivants.

Problème à résoudre

L'équipe disposait de maquettes plus abouties visuellement, mais il fallait encore les traduire en écrans web réellement intégrables, avec des composants assez stables pour être repris ensuite. Sans base commune, chaque nouvel écran risquait d'introduire des écarts de spacing, de hiérarchie ou de comportement.

Le projet revenait donc à résoudre un problème concret : intégrer un premier écran fidèle aux maquettes, puis réutiliser cette base sur les suivants sans re-régler chaque composant à la main.

Objectif technique

  • Créer une base de référence pour les composants et styles récurrents
  • Intégrer un écran Suivea v3 fidèle aux maquettes validées
  • Limiter les écarts visuels entre les écrans et les états d'interface
  • Préparer une structure plus réutilisable pour les futures intégrations

Ce que j'ai développé

J'ai d'abord contribué à la mise en place d'une page socle regroupant les styles et composants utiles au projet, puis nous avons intégré les écrans Suivea v3 en binôme à partir de cette base.

  • Structuration HTML des blocs métier avec une hiérarchie claire pour la lecture et la maintenance
  • Mise en place de styles réutilisables pour les boutons, champs, cartes, espacements et grilles
  • Ajustements fins de typographie, marges, alignements et densité visuelle pour coller aux maquettes
  • Vérification de cohérence entre écrans, variantes et états d'interface avant validation

Organisation en binôme

Le travail était découpé par lots clairs (structure, composants, intégration, retours), avec des points réguliers pour aligner le rendu final. Cette organisation a permis d'éviter les divergences de style, de répartir proprement l'avancement et de corriger vite les écarts repérés.

Difficultés d'intégration

  • Traduire précisément la maquette en code sans perdre la hiérarchie visuelle prévue
  • Éviter les variations d'un écran à l'autre sur les composants récurrents
  • Arbitrer entre fidélité visuelle, contraintes de temps et niveau de finition atteignable

Une partie importante du travail a consisté à corriger les écarts qui paraissent mineurs isolément mais qui dégradent vite la perception globale d'une interface : marges incohérentes, alignements imparfaits, tailles de texte trop proches ou composants visuellement "presque" identiques.

Résultats

  • Base composants suffisamment structurée pour servir de point d'appui aux écrans suivants
  • Écran Suivea v3 intégré de manière fidèle et validé en interne
  • Meilleure cohérence visuelle entre les blocs et les états d'interface
  • Montée en rigueur sur l'intégration UI en contexte professionnel et collaboratif

Ce que ce projet m’a permis de développer

  • Capacité à transformer une intention graphique en interface web exploitable
  • Attention réelle aux détails d'intégration qui font la qualité perçue d'un produit
  • Travail en binôme avec alignement continu sur un rendu commun
  • Réflexe de structuration pour éviter de produire du code jetable écran par écran
